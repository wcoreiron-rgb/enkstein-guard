### Found by the production-profile harness checks (fixed in source)

- F-6 (rc1, latent): the egress proxy kept a tunnel until both directions closed;
  a destination that delays its own close (the synthetic TLS upstream waits for
  close_notify) held a proxy slot for up to 30 s, so at 20 req/s the proxy hit
  `max_connections` and answered 503: 54 % of requests became outcome unknown.
  Fix: once Guard closes its end, the proxy ends the tunnel after a 0.25 s grace
  (`tests/test_egress.py::test_tunnel_released_when_guard_closes_even_if_destination_lingers`).
- F-7: connector worker-slot exhaustion (4 per connector) and tunnel/TLS setup
  failures were reported as outcome unknown although nothing was sent. Now
  `unavailable_no_execution` with fixed reasons (`connector_busy`,
  `egress_denied_503`, `egress_unavailable`, `provider_tls_failed`, ...);
  `max_concurrent_calls` per connector (default 16); fixed failure reason codes
  recorded in audit for unknown outcomes.
- F-8: a refused connection (busy/denied) was closed with the request unread, so
  on Unix sockets the client got a reset instead of the answer (indistinguishable
  from an unknown outcome). The service now discards input briefly before
  closing; `guarded_request` reads the answer after a failed write.
- `outcomes list` no longer opens the ledger from a second process while the
  service runs (that would mark in-flight records uncertain); it asks the service.

### AI-assisted review of the rc2 changes (2026-10-28, separate subagent; not independent)

Findings and resolution (all fixed before the final evidence run, which was
restarted from scratch after the fixes):

1. Medium: retention chunks recounted `tenant_counts` with a full scan and ran
   back to back, so at 1 M records request-path ledger writes could wait past the
   5 s busy timeout; a failed completion write turned a completed action into an
   unknown outcome. Fix: per-tenant counts decremented per archived row, 50 ms
   pause between chunks, audit chunks of 5,000 events, scheduled runs skip the
   retained pass (chunked when run), settlement retries capped per pass, and a
   completed action whose ledger write fails is still released (no replay: the
   state is kept in memory; uncertain after restart).
2. Medium: `data_domain` replaced the tenant/destination key, so a domain on one
   of two connectors to one host split that backend (label stripping). Fix:
   backends are connected components of both keys (a domain only joins).
3. Medium: the register check treated `blocked_known_gaps` as accepted. Fix: only
   `scoped_scenarios_passed` counts as accepted.
4. Medium: evidence-check had an exemption option and no per-report digests, and
   ignored lock matches. Fix: no exemptions, digests recorded and compared by the
   register check, exact lock match required for Linux and image reports.
5. Low: segment directory entries were not fsynced before deletion. Fixed.
6. Low: `--include-uncertain` could archive a request in flight; segment list not
   reconciled with the policy counter. Both fixed.
7. Low: shared provider secrets were refused only at `secret-set`. Production
   start now refuses them.
8. Low: refused-connection draining had no concurrency bound. Now at most 8 at a
   time, at most 1 MiB each, 0.1 s.
